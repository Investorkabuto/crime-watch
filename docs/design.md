# Crime Watch 設計書（公開サイト）ドラフト v0.1

最終更新: 2026-11-27
対応する要件: `docs/requirements.md` v0.20（特に §0 基本方針、F7 公開サイト、F9 公開 API、§6 量刑指標、§9 法的配慮、§13.8 テーマ）

この設計書は「何をどう作るか」を決めるための資料。要件定義書が「何を満たすか」、この設計書が「どう実現するか」を受け持つ。
いまできているのは受信・保存・管理画面までで、一般向けの公開サイトはまだない（`SITE_PUBLIC="false"`）。本書はその公開サイトの設計を中心に、既存部分の構成もまとめる。

## 1. 設計の原則

| # | 原則 | 設計への落とし込み |
|---|---|---|
| P1 | **事実のみを記載する**（要件 §0） | 画面の文言は件数・数値・記事に書かれた事実だけ。「甘い」「厳しい」「多い」「危険」などの評価語、ランキング、評価の色分け（赤＝悪い等）を使わない |
| P2 | **数字は独り歩きさせない** | 平均値には必ず件数と 95% 信頼区間を添える。件数の下限に届かない集計は出さない（§6.3） |
| P3 | **個人を特定しない** | 被告人・被害者の氏名・顔写真・番地・学校名・勤務先は持たない。著名人は「某歌手」の形で表示（§13.8） |
| P4 | **確定前は推定無罪** | 確定していない事件のページには必ず「有罪が確定したものではありません」を出す |
| P5 | **出典に戻れる** | すべての事件・判決に出典リンクを出す。記事本文は転載しない |
| P6 | **SNS から来た人が 1 画面で分かる** | 事件ページの上半分だけで「何が起きて、今どこまで進んでいるか」が分かる構成 |
| P7 | **速く、安く** | 公開ページは HTML をサーバー側で作り、CDN にキャッシュする。D1 の無料枠に収める |

## 2. システム全体構成

```
                 ┌──────────────────────── Cloudflare ────────────────────────┐
  Muse（もち）    │  Worker: crime-watch（Hono）                                │
  ── POST ──────▶│   /api/v1/ingest  検証 → 分類 → 保存 → テーマ・進み具合を更新 │
  （HMAC 署名）   │                                    │                        │
                 │                                    ▼                        │
  閲覧者          │   公開ページ（HTML）◀── 読み取り ── D1（crime-watch）        │
  ── GET ───────▶│   /, /cases/..., /themes/... 等        ▲                     │
     ▲           │   公開 API /api/v1/...                │                     │
     │           │   Cron（1 時間ごと）── 集計テーブルを作り直す                 │
  CDN キャッシュ   │                                                            │
                 │   /admin（管理画面）── Cloudflare Access ＋ VIEWER_TOKEN     │
                 └────────────────────────────────────────────────────────────┘
```

- **1 つの Worker** に受信 API・公開ページ・公開 API・管理画面を同居させる（いまの構成を続ける）。分ける必要が出るまでは分けない
- **公開ページは Worker が HTML を返す**（サーバー側レンダリング）。React などのクライアント側の仕組みは使わず、検索エンジンと SNS のプレビューにそのまま読まれる形にする。グラフ（量刑バー・推移）は SVG をサーバー側で作る
- **公開の切り替え**は今の `SITE_PUBLIC` をそのまま使う。`"false"` の間は公開ページも公開 API も `VIEWER_TOKEN` がないと見えない
- 管理画面は今どおり `/admin`。公開前に Cloudflare Access をかける（要件 F8）

### 2.1 既存モジュールの役割（参考）

| モジュール | 役割 |

| `src/classify.ts` | 罪状 → 法律の自動判定 |

| `src/admin.ts`, `admin-page.ts` | 管理画面と管理用 API |

### 2.2 追加するモジュール

| モジュール | 役割 |

## 4. 画面ごとの設計

### 4.1 共通の枠

```
┌──────────────────────────────────────────────────────────────┐
│ Crime Watch   事件  テーマ  法律  都道府県  統計     [検索____] │
├──────────────────────────────────────────────────────────────┤
│ ⚠ AI が報道から自動で集めて分類した情報です。誤りを含む場合が     │
│   あります。出典の記事をご確認ください。         [訂正を依頼]    │
├──────────────────────────────────────────────────────────────┤
│                         （各画面）                             │
├──────────────────────────────────────────────────────────────┤
│ このサイトについて ｜ この数字について ｜ 削除・訂正の依頼 ｜ RSS │
└──────────────────────────────────────────────────────────────┘
```

- AI の注意書き（要件 §9-9）は全ページに出す。スマホでは 1 行に縮める
- スマホを主に設計する（SNS から来る人の多くはスマホ）。横幅 360px で崩れないこと
- ダークモードに対応する（色は CSS 変数で定義）

### 4.2 事件ページ `/cases/:id`（最重要）

SNS から最も多く来る画面。上半分で「何が・どこで・今どうなっているか」が分かるようにする。

```
┌──────────────────────────────────────────────┐
│ [強盗] [闇バイト・トクリュウ]   ← テーマのタグ   │
│ 住宅に押し入り現金を奪った強盗致傷事件            │  ← title（Muse の要約見出し）
│ 東京都 江東区 ・ 2026年3月12日発生               │
│                                              │
│ 進み具合                                       │
│ ●発生 ─ ●逮捕 ─ ●起訴 ─ ●一審判決 ─ ○控訴審 ─ ○確定 │  ← cases.progress
│                                   ↑いまここ     │
│ ┌ 有罪が確定したものではありません ┐  ← 確定前のみ  │
│                                              │
│ 要約                                           │
│ （Muse が書いた要約。記事の転載はしない）          │
│                                              │
│ 一審判決 2026年10月2日 東京地裁                  │
│ 拘禁刑 9年（求刑 12年）                          │
│ 3年 ├─────────●───────▲──────────────┤ 20年      │  ← 量刑バー（§4.2.1）
│      判決 9年   求刑 12年                        │
│      法定刑の幅の 35% ・ 求刑の 75%               │
│ 裁判長 ○○ ○○  裁判官 … （裁判官ページへのリンク）  │
├──────────────────────────────────────────────┤
│ 時系列                                         │
│ 2026-03-12 発生   出典: ○○新聞                  │
│ 2026-04-02 逮捕   警視庁 深川署  出典: …          │
│ 2026-04-23 起訴   東京地検      出典: …          │
│ 2026-10-02 一審判決 東京地裁    出典: …          │
├──────────────────────────────────────────────┤
│ 被疑者・被告人（人ごと）                          │
│  男性 ・ 20代 ・ 無職 ・ 国籍: 記載なし            │
│  罪状: 強盗致傷 → 刑法 240 条                    │
│ 被害者（大まかな属性のみ）                        │
│  女性 ・ 70代                                   │
│ 事件の状況: 動機… ・ 凶器… ・ 共犯 3 人            │
├──────────────────────────────────────────────┤
│ 同じテーマの最近の事件 ／ 同じ都道府県の最近の事件    │
│ [X でシェア] [LINE で送る] [URL をコピー]          │
│ [この事件の訂正・削除を依頼]                      │
└──────────────────────────────────────────────┘
```

**表示ルール**
- 見出し・要約は Muse の文章をそのまま出す。著名人は区分のみ（「某歌手」）。`public_figure` があるときは見出しの前に「某{区分}」のバッジを出す
- 人物の属性は、記事に書かれていたものだけ出す。書かれていない項目は「記載なし」と出し、推測で埋めない（国籍も同じ。記載なし＝日本国籍とはしない）
- 年齢は記事どおり（例「34歳」）。少年事件も同じ（要件 §9-3）。被害者は年代まで
- 罪状は「記事の表記 → 判定した法律」を並べ、未分類のものは「未分類」と出す（隠さない）
- 不起訴・処分保留は、理由が記事にあれば出す（`non_prosecution_reason`）
- 再逮捕が複数あるときは時系列にそのまま並べる
- `status = hidden` の事件は 410 と「この事件は非公開になりました」だけを返す

#### 4.2.1 量刑バー

要件 F7 の図を SVG で描く。

- 横軸は**行為時の法定刑**（`law_penalty_periods`）の下限〜上限。主たる罪（最も重い罪）の法定刑を使う
- 判決は●、求刑は▲。執行猶予付きは●を白抜きにし、横に「執行猶予 4年」
- 背景に、同じ罪名・同じ審級の判決の分布（25〜75% の帯と中央値の線）を薄く重ねる。件数が 20 件未満なら重ねない
- 併合罪・未遂などで法定刑の幅を超える場合は、バーの端に「法定刑の幅を超えています（加重の可能性）」と事実だけ書く
- 死刑・無期・罰金のみ・無罪・不定期刑はバーを出さず、文字だけで示す
- 色は 1 色（判決）と 1 色（求刑）だけで、良し悪しを表す色は使わない
- 法定刑の確認（§10 の R1）が済んでいない法律では、バーの下に「法定刑は確認中」と出す

### 4.3 テーマ別ページ `/themes/:theme`（SNS の入口）

```
┌──────────────────────────────────────────────┐
│ 闇バイト・トクリュウ                              │
│ 記事に「闇バイト」「トクリュウ」と書かれた事件       │  ← テーマの判定基準を必ず書く
│                                              │
│ 2026年の件数  124 件   うち判決 31 件             │
│ 月ごとの件数  ▁▂▃▅▆▇▅▆▇█▇  （SVG の棒グラフ）      │
│ 都道府県  東京 32 ・ 大阪 18 ・ 愛知 11 …          │
│ 進み具合  捜査中 70 ・ 公判中 23 ・ 判決 31         │
│                                              │
│ 最近動きのあった事件                              │
│  11/26 起訴   ○○の強盗事件      東京都            │
│  11/25 一審判決 拘禁刑 6年  …    千葉県            │
│  …                         [もっと見る → /cases?theme=…] │
│ [このテーマの RSS]                               │
└──────────────────────────────────────────────┘
```

- テーマごとに「どういう事件をこのテーマにしているか」を必ず書く（自動の判定条件、または「記事に書かれている場合に Muse が付ける」）。要件 §13.8 の表をそのまま使う
- 件数は「報道された事件の件数」であり、発生件数ではないことを件数の横に書く
- 「外国人犯罪」も他のテーマと同じ形で出す（要件 §13.6、全公開）。件数は人単位で、記載なしは別に数えて出す

### 4.4 トップ `/`

```
┌──────────────────────────────────────────────┐
│ 最近動きのあった事件（latest_at の新しい順 10 件）   │
│ 今日の判決（判決日が今日のもの）                    │
│ 注目のテーマ（直近 7 日で件数が多い順に 8 個のタグ） │  ← 並べ順は件数のみ。「話題」等の語は使わない
│ 今週の件数  報道 312 件 ・ 判決 87 件               │
│ 法律の大分類ごとの件数（刑法犯・交通・薬物 …）        │
└──────────────────────────────────────────────┘
```

### 4.5 事件一覧 `/cases`

- 絞り込み: 期間、都道府県（発生地／警察／裁判所の別）、法律、大分類、テーマ、進み具合、少年事件、判決ありのみ
- キーワード検索: 見出し・要約・罪状の文字列（D1 の LIKE。件数が増えたら FTS5 に切り替える）
- 並べ替え: 最近動きがあった順（初期値）、発生日順
- 1 ページ 30 件、`?page=` でページ送り。絞り込み条件は URL に残し、そのまま共有できるようにする
- 管理用の絞り込み（非公開・要確認）は公開画面には出さない

### 4.6 法律別ページ `/laws/:code`

- 法律名、条文番号、法定刑（期間ごとの変更履歴つき。例: 強制性交等 → 不同意性交等）、e-Gov へのリンク
- 件数の推移、判決の刑期の分布（箱ひげ）、執行猶予率
- 性別・年代別の指標 A〜D（要件 §6.4）。件数の下限と信頼区間のルールを守る。差の理由の解釈は書かない

### 4.7 都道府県別ページ `/prefectures/:name`

- 件数（発生地ベースが初期値。警察・裁判所ベースに切り替え可）、法律別・テーマ別の内訳、市区町村別の件数（上位）、最近の事件
- 人口 10 万人あたりの値は、出典（総務省の人口推計）を明記できるようになってから出す（§10 の未決事項）

### 4.8 統計 `/stats`

- 期間 × 法律 × 都道府県のクロス集計表（CSV ダウンロード付き。要件 F9）
- 性別・年代・職業・国籍・在留資格の内訳。国籍は人単位、記載なしを必ず別に出す
- どの表にも「報道された事件・判決に基づく集計で、全事件ではありません」を出す

### 4.9 裁判官別 `/judges/:id`・裁判所別 `/courts/:id`

- 要件 §6.2・§6.3 をそのまま守る:
  - 件数の下限（初期値 20 件）未満は、判決の一覧だけ出す
  - 平均値には件数と 95% 信頼区間を出す。区間が 0 をまたぐときは「全体との差は統計的に明確ではない」と表示
  - 主に集計するのは単独事件と合議の裁判長。陪席は一覧のみ。裁判員裁判は別枠
  - ランキング、並べ替えて比べる一覧、色による評価は作らない（裁判官の一覧ページは作らず、判決から辿る形にする）
- 同姓同名の名寄せが済むまで（要件 F8）、裁判官ページは試行として公開を遅らせられるようにする（設定 `JUDGE_PAGES_PUBLIC`）

### 4.10 このサイトについて `/about`・この数字について `/about/metrics`

- 基本方針「事実のみを記載する」、データの集め方（AI が報道から収集）、AI の誤りの可能性、出典の扱い、著名人・少年事件の表示の方針、削除・訂正の依頼の方法
- 指標の定義・計算式・限界（報道による偏り、前科・示談などを考慮していないこと）を、要件 §6 から書き起こす

### 4.11 削除・訂正の依頼 `/contact`

```
依頼の種類   ( ) 内容の誤り  ( ) 削除の依頼  ( ) その他
対象の事件   [https://…/cases/… ]   ← 事件ページから来たときは自動で入る
内容         [                        ]
連絡先（任意）[メールアドレス          ]
                                   [送信]
```

- 送信内容は D1 の `requests` テーブルに保存し、管理画面に「依頼」タブを作る（§7.2）
- **削除の依頼が来たら、その事件を自動で一時非公開にする**か、管理者の確認を待つかは未決（§10）。初期案は「自動で一時非公開、管理者が確認して戻す／消す」（要件 §9-10）
- スパム対策に Cloudflare Turnstile を使う

## 5. SNS からの集客の設計

| 項目 | 設計 |
|---|---|
| 見出し（`<title>`、`og:title`） | 事件: `{見出し}｜{都道府県}・{進み具合}｜Crime Watch`。テーマ: `{テーマ}の事件 {件数}件（2026年）｜Crime Watch` |
| 説明（`og:description`） | 事件: 要約の先頭 80 字＋判決があれば「拘禁刑 9年（求刑 12年）」 |
| プレビュー画像（`og:image`） | 第 1 段階: テーマ・大分類ごとの固定画像（事前に作って配信）。第 2 段階: 事件ごとに「見出し・進み具合・量刑バー」を描いた画像を生成し、キャッシュする |
| シェアの文面 | 「{見出し}（{進み具合}） #CrimeWatch #{テーマ}」。ハッシュタグはテーマ名のみで、煽る語は入れない |
| 追いかけたくなる仕組み | 事件ページに「この事件の続報を受け取る」＝事件ごとの RSS。テーマ別 RSS |
| 公式アカウントへの投稿 | 判決・起訴など段階が進んだ事件を投稿する。自動にするか手動にするかは未決（§10）。文面は上の「シェアの文面」と同じ規則 |
| 検索エンジン | `sitemap.xml`（事件・テーマ・法律・都道府県）、構造化データ（`NewsArticle` ではなく `Dataset`／`WebPage`。記事の転載と誤解されないため） |

## 6. キャッシュと性能

- 公開ページは `Cache-Control: public, s-maxage=300, stale-while-revalidate=3600` を付け、Cloudflare の CDN にキャッシュする。受信から最大 5 分で反映される
- 事件ページは段階が進むと中身が変わるので、キャッシュの鍵に `cases.updated_at` を含めず、短い有効期限（5 分）で更新する。非公開にしたときは管理画面からその URL のキャッシュを消す（Cache API の `delete`）
- 集計（テーマ・都道府県・統計・裁判官）は毎回 D1 で集計せず、§7 の集計テーブルから読む
- 目標: キャッシュに当たれば 50ms、外れても 300ms 以内。D1 の読み取りは 1 ページあたり 10 クエリ以内

## 7. データの追加

### 7.1 集計テーブル（Cron で 1 時間ごとに作り直す）

| テーブル | 中身 | 使う画面 |
|---|---|---|
| `agg_theme_monthly` | テーマ × 月 × 都道府県の件数 | テーマ別、トップ |
| `agg_law_monthly` | 法律 × 月 × 都道府県の件数 | 法律別、統計 |
| `agg_sentence_dist` | 法律 × 審級ごとの刑期の分布（中央値・四分位・件数） | 量刑バーの背景、法律別 |
| `agg_judge_metrics` | 裁判官 × 役割 × 罪名（＋全罪名）の件数・平均・信頼区間・執行猶予率 | 裁判官別 |
| `agg_court_metrics` | 裁判所 × 罪名の同じ指標 | 裁判所別 |

- 作り直しは「消して、集合演算の SQL で入れ直す」を 1 回の batch で行う（`recomputeThemes` と同じ方式）
- 信頼区間は SQL で平均・標準偏差・件数を出し、Worker 側で計算する（t 分布の近似）
- 公開しない事件（`status = 'hidden'`）は集計に入れない

### 7.2 その他のテーブル

| テーブル | 中身 |
|---|---|
| `requests` | 削除・訂正の依頼（種類、対象の事件、内容、連絡先、状態、受け付けた日時、対応メモ） |
| `admin_actions` | 管理者の操作の記録（要件 §8 の監査）。非公開化・依頼への対応・罪状辞書の追加など |
| `laws.verified_at`, `laws.source_url` | 法定刑を e-Gov で確認した日と、確認した条文の URL（§10 の R1） |

マイグレーションは `0011_public_site.sql` にまとめ、これまでどおり D1 コンソール用の SQL も用意する。

## 8. 公開 API（要件 F9）

公開サイトと同じデータを JSON で出す。今の `/api/v1/cases` などはそのまま使い、公開時に次を加える。

| API | 中身 |
|---|---|
| `GET /api/v1/themes` | テーマの一覧と件数 |
| `GET /api/v1/stats?group=law,prefecture&from=&to=` | 集計（集計テーブルから） |
| `GET /api/v1/judges/:id` | 裁判官の判決一覧と指標（下限ルールを守る） |
| `GET /api/v1/export/judgments.csv` | 量刑データの CSV（研究・報道での検証用） |

- 公開 API にはレート制限をかける（Cloudflare の Rate Limiting ルール）
- 管理用の項目（`flagged`、要確認の内容、非公開の事件）は公開 API では返さない。今の API は `SITE_PUBLIC` の切り替えと同時に、管理用の項目を出さない形に分ける

## 9. 段階に分けた作り方

| 段階 | 作るもの | 公開の状態 |
|---|---|---|
| **S1** | 共通の枠、事件ページ（量刑バーつき）、事件一覧、テーマ別、トップ、about、contact（`requests`）、sitemap | 非公開のまま（`VIEWER_TOKEN` で mason が確認） |
