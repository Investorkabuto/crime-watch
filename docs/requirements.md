## 1. 概要

### 1.1 目的
日本国内で日々起きた犯罪の情報を集め、データとして蓄積し、**法律（罪名）ごとに分類して一般公開する** Web アプリケーション。
さらに、事件の**判決（量刑）と担当した裁判官**をデータにし、

- 法定刑の幅（例: 「3年以上10年以下」）の中で、実際に何年の刑が言い渡されたか
- 裁判官ごとに、量刑が全体と比べてどのくらい重い／軽いか（**数値のみで示し、「甘い」「厳しい」などの言葉による評価はしない**）
- 被告人の性別・年齢などの違いで量刑に差があるか

を、**事実のデータとして**分かりやすく見られるようにする。

### 1.2 役割分担

| 担当 | 内容 |
|---|---|
| **AI「Muse」**（本アプリの外） | ニュース・警察発表・判決報道などから情報を集め、構造化データにして**本アプリへ送信する** |
| **本アプリ（Crime Watch）** | Muse からデータを受け取り、検証・正規化し、**罪状から法律を自動で判定**して保存し、量刑指標を計算し、**すべて自動で公開**する |

### 1.3 スコープ
- 対象地域: **日本国内のみ**
- 公開範囲: **一般公開**（誰でも閲覧できる）
- 対象データ: 事件（発生・逮捕・送検・起訴）と判決（量刑・裁判所・裁判官・被告人の属性）。**少年事件も含む**（§9-3 のルールに従う）
- 交通事件: 悪質・重大なものは**すべて対象**とする
  - 対象: 飲酒運転（酒気帯び・酒酔い）、危険運転致死傷、過失運転致死傷、ひき逃げ（救護義務違反）、妨害運転（あおり運転）、無免許運転
  - 対象外: 速度超過・駐車違反など、反則金で済む軽微な違反（人身事故を伴うものは対象）
- 期間: 運用開始以降に加え、**過去のデータも取れる限り取り込む**（F10）
- 情報源: 主にニュースの報道。裁判所の裁判例検索は裏付け・補完に使う（性犯罪・少年事件は裁判例検索に載らないため）
- 対象外: データの収集・要約（Muse 側の責務）、SNS への投稿

## 2. システム構成

公開先は **Cloudflare Workers**。周辺サービスも Cloudflare でそろえる。

```
 ┌──────────┐  HTTPS POST /api/v1/ingest     ┌───────────────────────────────┐
 │   Muse   │ ─────────────────────────────▶ │  Cloudflare Worker (API)      │
 │  (AI)    │  Authorization: Bearer <token> │  - 認証 / レート制限            │
 └──────────┘                                │  - スキーマ検証・正規化         │
                                             │  - 罪状 → 法律の自動判定        │
                                             │  - 事件・判決のひも付け         │
                                             └──────┬────────────────────────┘
                                                    │ 事件・判決・受信データの原本
                                                    ▼
                                             ┌────────────┐
                                             │ D1 (SQLite) │
                                             │ 事件・判決   │
                                             │ 法律・裁判官 │
                                             │ 原本JSON     │
                                             │ 量刑指標     │◀── Cron Triggers（指標の再計算）
                                             └─────┬──────┘
                                                   │
 ┌──────────┐  GET /, /laws/:code, /api/...  ┌─────▼─────────────────────────┐
 │ 閲覧者    │ ◀───────────────────────────── │  Cloudflare Worker (公開サイト)│
 └──────────┘   (Cache API / CDN キャッシュ)  │  + Static Assets (画面)        │
                                             └───────────────────────────────┘
 ┌──────────┐  Cloudflare Access で保護
 │ 管理者    │ ─────▶ /admin（事後の確認・非公開化・修正）
 └──────────┘
```

| 要素 | 採用候補 | 用途 |
|---|---|---|
| 実行環境 | Cloudflare Workers（TypeScript） | API と公開サイト |
| Web フレームワーク | Hono | ルーティング・ミドルウェア |
| DB | Cloudflare D1 | 事件・判決・法律マスタ・裁判官・集計結果 |
| 原本の保存 | Cloudflare D1（`raw_payloads`） | 受信した JSON の原本（監査・再処理用）。量が小さいため R2 は使わない |
| 画面 | Workers Static Assets（SSR か SPA かは未決） | 公開サイト |
| 管理者認証 | Cloudflare Access | /admin の保護 |
| 定期処理 | Cron Triggers | 量刑指標の再計算、日次集計、未分類罪状の集計 |
| 非同期処理（必要時） | Cloudflare Queues | 大量受信時の取り込みの分散 |

## 3. 機能要件

### F1. データ受信 API（Muse → 本アプリ）【確定: push 方式】
- `POST /api/v1/ingest` で 1 件または複数件（上限は例えば 100 件）を受け取る
- 1 件のデータは「事件の報道（発生・逮捕・送検・起訴）」か「判決」のどちらか（§5）
- 過去データの取り込み（F10）は `backfill: true` を付けて送る。新着一覧・RSS・管理者通知の対象から外す
- 認証: Bearer トークン（Workers Secret に保存）。可能なら HMAC 署名も検証する
- **冪等性**: `external_id`（Muse 側 ID）で重複を判定し、同じ ID は更新として扱う。再送しても二重登録にならない
- レスポンスで件ごとの結果（`created` / `updated` / `rejected` と理由）を返す
- 受信データは原本のまま D1 に保存する（`raw_payloads`。v0.7 で R2 から変更）

### F2. 検証・正規化
- 必須項目の確認と型の検証（スキーマは §5）
- 都道府県名を正規化する（例: 「大阪府警」→ 大阪府）
- 日付を正規化する（JST、`YYYY-MM-DD`）
- 刑期を月数に換算する（例: 「拘禁刑2年6月」→ 30 か月）。罰金は円単位の整数にする
- 裁判所名・裁判官名を正規化する（全角・半角、空白、「地裁」→「地方裁判所」など）
- 年齢から年代（10代・20代…）を計算する。少年事件は §9-3 のルールで表示用の値を丸める
- 必須項目が欠けているなど、形式として壊れているデータのみ `rejected` で返す（内容による公開停止はしない。F4）

### F3. 法律の自動判定【確定: 本アプリが罪状から判定】
- Muse は**罪状をそのままの文字列**で送る（例: `"詐欺"`、`"住居侵入・窃盗"`、`"酒気帯び運転"`、`"覚醒剤取締法違反（使用）"`）
- 本アプリは**罪状辞書**（罪状の言い方 → 法律コード）で法律を判定する
  - 「住居侵入・窃盗」のように複数の罪状が並ぶ場合は区切って、それぞれ判定する
  - 「殺人未遂」のような未遂・幇助・共謀は、元の罪（殺人）に分類し、`attempt` などの付記を記録する
- 1 件が複数の法律に当てはまってよい（例: 強盗殺人 → 強盗罪＋殺人罪）
- 判定できなかった罪状は「未分類」として公開し、管理画面で一覧できるようにする。管理者が辞書に言い方を追加すると、過去のデータも再判定される

### F4. 自動公開【確定: 全件自動公開】
- 形式チェックを通ったデータは、**受信と同時にすべて公開する**。人による事前承認や保留はしない
- 自動チェック（§9-8）に引っかかったデータも公開は止めず、**管理者に通知して事後に確認する**
- 状態: `published`（公開）/ `hidden`（管理者が非公開化）/ `deleted`（論理削除）

### F5. 事件と判決のひも付け
- 同じ事件の報道（逮捕 → 送検 → 起訴 → 判決）を **1 つの「事件（case）」にまとめる**
- まとめ方: Muse が同じ事件に同じ `case_ref` を付けて送る（Muse 側で可能と確認済み）
  - Muse は、氏名の鍵付きハッシュ（§9-11）と、発生日・場所・被害内容などの複合一致でひも付けを判定する
  - ひも付けの確かさを `link_confidence`（`high` / `low`）で受け取る。`low` のものは事件ページで「関連の可能性がある報道」として分けて表示し、量刑指標の属性の引き継ぎ（下記）には使わない
- **属性の引き継ぎ**: 判決報道には性別が書かれないことが多い（試し取りで 0/5 件）。一方、逮捕報道には書かれることが多いため、`link_confidence: high` でひも付いた同じ事件の報道から、性別などの属性を判決データに引き継ぐ。引き継いだ値には「引き継ぎ」の印を付ける
- 控訴審・上告審の判決も同じ事件にひも付け、審級を記録する
- 共犯事件では被告人ごとに判決が分かれるため、**判決データは被告人 1 人につき 1 件**とする

### F6. 量刑・判決データ
判決（被告人 1 人ごと）に次の情報を保存し、公開する。

**判決の基本情報**
| 項目 | 内容・例 |
|---|---|
| 裁判所 | 東京地方裁判所、大阪高等裁判所 など |
| 審級 | 一審／控訴審／上告審／**不明**（報道に明記されないことが多いため任意。最高裁＝上告審のように確実な場合のみ埋める） |
| 判決日 | 2026-11-20 |
| 裁判官 | 氏名と役割（裁判長／右陪席／左陪席／単独）。報道から取れるのは主に裁判長・単独の裁判官まで |
| 裁判員裁判か | はい／いいえ |
| 認定された罪 | 判決で認められた罪。法律は F3 と同じ方法で判定 |

**刑の内容**
| 項目 | 内容・例 |
|---|---|
| 刑の種類 | 死刑／無期拘禁刑／有期拘禁刑／罰金／拘留／科料／無罪（2025年6月より前の判決は懲役・禁錮も記録） |
| 刑期 | 月数で保存（例: 30 か月）。表示は「2年6月」 |
| 不定期刑 | 少年に言い渡される「◯年以上◯年以下」の刑。下限・上限を月数で保存 |
| 執行猶予 | 有無と期間（例: 4 年）、保護観察付きか |
| 罰金額 | 円 |
| 求刑 | 検察の求刑（刑の種類・刑期・罰金） |
| 未決勾留日数の算入 | 日数（任意） |
| その他 | 没収・追徴など（任意） |
| 控訴の状況 | 控訴／上告／確定／不明。判決当日の報道には載らないため初期値は「不明」とし、続報で更新する |
| 少年の保護処分 | 家庭裁判所の処分（保護観察／少年院送致／児童自立支援施設等送致／不処分／審判不開始／検察官送致）。§9-3 |

**被告人の属性（新規）** — 量刑の差を事実として集計するため。**氏名は保存しない**
| 項目 | 内容・例 |
|---|---|
| 性別 | 男性／女性／不明 |
| 年齢 | 報道された年齢（例: 34）。分からなければ年代（例: 30代） |
| 少年か | 少年（18歳未満）／特定少年（18・19歳）／成人 |

**量刑に影響する事情（新規・任意）** — 裁判官どうしを公平に比べるための補正に使う
| 項目 | 内容・例 |
|---|---|
| 前科の有無 | 初犯／前科あり／不明（同種前科かどうかも分かれば） |
| 認否 | 認めている／否認／一部否認／不明 |
| 示談 | 成立／不成立／不明 |
| 被害額 | 円（財産犯） |
| 被害者数 | 人数 |
| 被害の結果 | 死亡／重傷／軽傷／なし／不明（身体犯） |
| 刑の加重・減軽 | 併合罪加重、再犯加重、未遂減軽、酌量減軽などの有無（判決で触れられていれば） |

### F7. 公開サイト
| 画面 | 内容 |
|---|---|
| トップ | 最新の事件・判決、今日・今週の件数、法律別の件数 |
| 事件一覧 | 絞り込み（日付範囲・都道府県・法律・大分類・段階）、キーワード検索、ページ送り |
| 事件詳細 | 要約・発生日・都道府県・該当法律・時系列・判決・出典リンク。判決には**量刑バー**（下記）を表示 |
| 法律別ページ | 法律の説明（条文・法定刑）、件数の推移、量刑の分布、性別・年代別の量刑比較 |
| 都道府県別ページ | 都道府県ごとの件数と事件一覧 |
| 裁判所別ページ | 裁判所ごとの判決一覧と量刑指標 |
| **裁判官別ページ** | 担当した判決の一覧と、§6 の量刑指標（全体平均との比較を数値で表示） |
| 統計 | 期間 × 法律 × 都道府県の集計、法律ごとの量刑比較、性別・年代別の比較 |

**量刑バー（判決 1 件ごとの表示）**

法定刑の幅の中で、求刑と判決がどこにあるかを 1 本のバーで示す。

```
窃盗罪（法定刑: 拘禁刑 1か月〜10年）
1か月 ├──────────●──────▲──────────────────────────────┤ 10年
                  判決 2年6月   求刑 3年6月
                  （法定刑の幅の 24% の位置／求刑の 71%）
                  執行猶予 4年
```

- 同じ罪名の判決全体の分布（中央値・ばらつき）も、バーの背景に薄く重ねる
- 執行猶予が付いた場合は、刑期の横に猶予期間を表示する

### F8. 管理機能（/admin、Cloudflare Access で保護）
- 事件・判決の非公開化・削除・修正（**削除依頼に素早く対応するため必須**）
- 自動チェックに引っかかったデータの事後確認
- 未分類の罪状の一覧と、罪状辞書への追加（追加後に再判定）
- 法律マスタ（法定刑を含む）・裁判所マスタの編集、裁判官の名寄せ（同姓同名・表記ゆれの統合と分離）
- 受信ログの閲覧

### F9. 公開 API / フィード（任意）
- `GET /api/v1/cases`、`GET /api/v1/judgments`、`GET /api/v1/laws`、`GET /api/v1/judges/:id`、`GET /api/v1/stats`
- RSS / Atom フィード（全体・法律別・判決のみ）
- 量刑データを CSV でダウンロードできるようにする（研究・報道での検証用）

### F10. 過去データの取り込み【新規】
- 試行期間中から、過去の報道・判決を**取れる限り取り込む**
- 取り込み順は**新しいものから過去へ**さかのぼる。まず直近 1 年分、次に不同意性交等罪などの改正（2023年7月）以降、その先は取れる範囲で
- 過去データは `backfill: true` を付けて送る。通常の受信と同じ API・同じ検証で取り込み、同じように公開するが、新着一覧・RSS・管理者通知には出さない
- 過去の判決は、当時の刑の名前（懲役・禁錮など）と、**行為の時点で有効だった法定刑**（§4 `law_penalty_periods`）で記録・計算する
- 古い記事は削除されて出典 URL が切れることがある。記事の本文は保存しない（転載になるため）ので、リンク切れは許容し、確認日（`source_checked_at`）を記録する
- 取り込みのペースは Muse の利用枠と、ニュースサイトへの負荷（アクセス間隔・利用規約）に合わせる。1 日の上限は試行で決める

## 4. データモデル（D1）

```
cases（事件） 1 ──── * reports（報道：発生・逮捕・送検・起訴）
   │
   ├── * case_charges（罪状 → 法律）
   │
   └── * judgments（判決：被告人1人につき1件） 1 ──── * judgment_judges * ──── 1 judges（裁判官）
             │                                                         courts（裁判所）
             └── * judgment_charges（認定された罪 → 法律）
laws（法律マスタ・法定刑） 1 ──── * charge_aliases（罪状辞書）
judge_metrics / law_metrics（量刑指標の集計結果。Cron で再計算）
```

```sql
-- 法律マスタ（法定刑を数値でも持つ）
CREATE TABLE laws (
  code              TEXT PRIMARY KEY,   -- 例: 'theft'
  name              TEXT NOT NULL,      -- 例: '窃盗罪'
  law_name          TEXT NOT NULL,      -- 例: '刑法235条'
  category          TEXT NOT NULL,      -- '刑法犯' | '特別法犯'
  group_name        TEXT NOT NULL,      -- '凶悪犯' | '窃盗犯' | '薬物' など
  statutory_penalty TEXT,               -- 法定刑の文言（表示用）
  stat_min_months   INTEGER,            -- 有期拘禁刑の下限（月）
  stat_max_months   INTEGER,            -- 有期拘禁刑の上限（月）
  stat_has_death    INTEGER NOT NULL DEFAULT 0,
  stat_has_life     INTEGER NOT NULL DEFAULT 0,
  stat_max_fine_yen INTEGER,            -- 罰金の上限（選択刑として罰金がある場合）
  sort_order        INTEGER NOT NULL DEFAULT 0
);

-- 法定刑の時期ごとの値（法改正で変わるため。指標 A は行為時点の値で計算する）
CREATE TABLE law_penalty_periods (
  law_code          TEXT NOT NULL REFERENCES laws(code),
  effective_from    TEXT NOT NULL,      -- 施行日
  effective_to      TEXT,               -- NULL = 現行
  statutory_penalty TEXT NOT NULL,
  stat_min_months   INTEGER,
  stat_max_months   INTEGER,
```

## 6. 量刑指標の定義（裁判官・裁判所・属性ごとの比較）

「甘い」「厳しい」といった言葉は使わず、**数値と件数だけ**で示す。指標は判決 1 件ごとに計算し、裁判官・裁判所・性別・年代などの単位で集計する。

### 6.1 判決 1 件ごとの指標

| 指標 | 計算式 | 例 | 意味 |
|---|---|---|---|
| **A. 法定刑内の位置** | (刑期 − 法定刑の下限) ÷ (上限 − 下限)。法定刑は**行為の時点**の値（`law_penalty_periods`） | 窃盗（1か月〜10年）で 2年6月 → 24% | 法定刑の幅の中のどこか。0% = 下限、100% = 上限 |
| **B. 求刑比** | 判決の刑期 ÷ 求刑の刑期 | 求刑 4年 → 判決 3年 = 75% | 検察の求刑に対してどのくらいの刑か |
| **C. 同種判決との比較** | 判決の刑期 ÷ 同じ罪名・同じ審級の判決の中央値 − 1 | 中央値 2年 → 判決 3年 = +50% | 同じ罪の判決全体と比べて重いか軽いか |
| **D. 執行猶予** | 付いた／付かない | — | 集計して「執行猶予率」にする |

- 計算の基準は、認定された罪のうち**最も重い罪**（`is_primary`）とする
- 併合罪加重・未遂減軽・酌量減軽などがあると、実際に選べる刑の幅（処断刑）は法定刑と違う。指標 A は「法定刑を基準にした目安」として表示し、加重・減軽がある判決には印を付ける
- 死刑・無期・罰金のみ・無罪は、有期刑の指標とは別に、件数と割合で示す
- 少年の不定期刑は、下限と上限の中間値を参考値として使い、成人の判決とは分けて集計する

### 6.2 裁判官ごとの集計

判決は 1 日 20 件程度と見込まれ、「同じ罪名で 20 件以上」に達する裁判官はなかなか出ない。そこで次の 2 段構えにする。

- **全罪名まとめた指標（主）**: 指標 C（同じ罪名の中央値との比較）と指標 B（求刑比）は罪名の違いをならした値なので、**罪名をまたいで裁判官ごとに平均**できる。これを裁判官ページの主な数字にする
- **罪名ごとの指標（従）**: 件数が下限に達した罪名だけ、罪名別の数字も出す

| 表示項目 | 例 |
|---|---|
| 判決件数 | 窃盗 34 件（裁判長・単独として） |
| 求刑比の平均 | 78%（全体平均 80%） |
| 同種判決との比較の平均 | −6%（95% 信頼区間 −11%〜−1%） |
| 執行猶予率 | 62%（全体 58%） |
| 法定刑内の位置の分布 | 箱ひげ図 |

表示の例（文章ではなく数値で示す）:

```
裁判官 山田 太郎（大阪地方裁判所）— 窃盗罪
  件数        34件（裁判長・単独として）
  求刑比      平均 78%   ｜ 全国平均 80%
  同種比較    −6%       ｜ 95%信頼区間 −11%〜−1%
  執行猶予率  62%       ｜ 全国平均 58%
```

### 6.3 公平に比べるためのルール

裁判官によって担当する事件の重さは違う（被害額が大きい事件が集まる部など）。数字だけが独り歩きしないよう、次のルールを設ける。

1. **件数の下限**: 罪名ごとに一定件数（初期値 20 件）未満の裁判官は、平均値や比較を表示しない（判決の一覧だけ出す）
2. **信頼区間を必ず出す**: 平均値には 95% 信頼区間と件数を必ず添える。区間が 0 をまたぐ場合は「全体との差は統計的に明確ではない」と表示する
3. **役割を分ける**: 単独事件と、合議事件の裁判長を主な集計対象にする。陪席裁判官は「担当した判決の一覧」のみとする（合議の判断を個人に帰属させにくいため）
4. **裁判員裁判は分ける**: 裁判員裁判は市民の裁判員も量刑を決めるため、裁判官個人の指標とは別枠で集計する
5. **補正の範囲**: 前科・示談・刑の加重減軽は、報道からはほぼ取れない（試し取りで 0/5 件）。そのため、これらで補正した比較は行わない。代わりに、取れる事情（認否・被害額・被害の結果・裁判員裁判か）で**分けて**表示し、それ以外の事情は考慮していないことを明記する
6. **計算方法の公開**: 指標の定義・計算式・データの出典と限界を「この数字について」ページで公開する
7. **報道による偏り**: 元データは「報道された事件・判決」に限られ、全判決ではない。報道されやすい重大事件や話題の事件に偏ることを、指標のページに明記する

### 6.4 性別・年齢などの属性別の集計

- 法律別ページ・統計ページで、被告人の性別・年代ごとに指標 A〜D を集計して表示する
- 表示ルールは §6.3 と同じ（件数の下限、信頼区間、補正の有無の明示）
- 「差がある」ことは示しても、その理由（差別があるか等）の解釈は表示しない。事実の数値のみとする

## 7. 法律分類マスタ（初期案）

警察統計の区分（刑法犯／特別法犯）を大分類にし、その下に中分類 → 罪名の 3 階層とする。各法律に法定刑を**数値で**持たせ（§4 `stat_min_months` など）、指標 A の計算に使う。法定刑の値は実装時に e-Gov 法令検索で確認して登録する。

| その他刑法犯 | 公務執行妨害、住居侵入、器物損壊、略取・誘拐、過失致死傷、死体遺棄 |

| 性能 | 公開ページは CDN キャッシュで応答 200ms 以内を目標。受信 API は 100 件/リクエストを 10 秒以内に処理 |

| 可用性 | Cloudflare のサービスレベルに従う。受信に失敗したら Muse 側で再送する（冪等なので再送しても安全） |
| セキュリティ | 受信 API はトークン認証＋レート制限。管理画面は Cloudflare Access。秘密情報は Workers Secrets |
| 監査 | 受信原本を D1 に保存。管理者の操作ログを残す |
| データ保持 | 保持期間は未決（§10） |
| コスト | まずは Workers / D1 の無料枠で運用 |
| 運用 | wrangler で環境を分ける（dev / prod）、GitHub Actions でデプロイ |

## 9. 法的・倫理的配慮（重要）

AI が集めたデータを**人の確認なしに、すべて自動で一般公開する**ため、事前に止める仕組みがない。そのぶん、**受け付けるデータの形と、事後の対応**で安全を確保する。

1. **裁判官以外の個人名は載せない**: 被告人・被疑者・被害者などの氏名、顔写真、住所は受け付けず、保存もしない
2. **裁判官のデータ**: 裁判官名は、公務として行った判決の情報として載せる。ただし、
   - 量刑は §6 の数値と件数だけで示し、「甘い」「厳しい」などの言葉、ランキング、色分けによる評価はしない
   - 件数の下限・信頼区間・担当事件の偏りの注意書きを必ず添える（§6.3）
   - 同姓同名の取り違えが起きうるので、裁判所と時期で名寄せし、管理画面で修正できるようにする
3. **少年事件（対象に含める）**: 少年法 61 条により、本人を推知できる情報は載せてはならない。属性データを組み合わせると個人が特定されるおそれがあるため、少年事件は次のように扱う
   - 市区町村は表示しない（都道府県まで）
   - 年齢は区分（「少年」「特定少年（18・19歳）」）だけを表示し、正確な年齢は表示しない
   - 学校名・勤務先などは受け付けない
   - 特定少年が起訴された場合、法律上は実名報道が可能になるが、本アプリでは成人も含めて氏名を載せないので扱いは同じ
   - 家庭裁判所の少年審判は非公開で、処分の情報は報道で分かる範囲に限られる
4. **属性の組み合わせによる特定**: 性別・年齢・地域・日付・罪名を組み合わせると、成人でも本人が特定されうる。表示する属性の粒度（年齢を年代で表示するか等）は弁護士と確認して決める
5. **前科などの扱い**: 前科は個人情報保護法の「要配慮個人情報」に当たる情報。本アプリは氏名を持たないが、§9-4 の特定リスクと合わせて、前科の有無を公開ページに出すか（集計にだけ使うか）を決める必要がある（§10 Q6）
6. **推定無罪の表記**: 判決が確定していない事件には「有罪が確定したものではありません」と表示する
7. **出典は必須・転載しない**: 出典 URL のないデータは受け付けない。記事本文や見出しをそのまま載せず、Muse が書いた要約と出典リンクにとどめる
8. **自動チェック（公開は止めない）**: 受信時に、裁判官欄以外に人名らしき文字列・電話番号・番地までの住所・学校名などがないかを機械的に検出し、見つかったら `flagged` を立てて管理者に通知する。少年事件では特に厳しく検出する
9. **AI の誤りへの備え**: 「AI が自動で収集・分類した情報で、誤りを含む場合があります」と全ページに明記する
10. **削除・訂正依頼の窓口**: 問い合わせフォームを設け、受け付けたら一時的に非公開にできる運用を用意する
11. **ひも付け用の氏名ハッシュ（決定）**: 事件のひも付けのため、Muse は被疑者・被告人の氏名をハッシュにして保存し、照合に使う。条件は次のとおり
    - **鍵付きハッシュ（HMAC-SHA256 など）を使う**。日本人の氏名は種類が限られるため、鍵のない単純なハッシュは総当たりで元の氏名に戻せてしまう
    - 鍵は Muse 側の秘密情報として保管し、Notion・リポジトリ・本アプリには置かない
    - 氏名は表記をそろえてからハッシュにする（空白の除去、全角・半角、旧字体など）
    - ハッシュは **Muse 側にだけ保存し、本アプリには送らない**。本アプリが持つのは `case_ref` と `link_confidence` だけ
    - ハッシュも個人情報保護法上の個人情報（仮名化された情報）として扱う。保存期間は次のとおり（v0.6 で確定）
      - 判決の確定が確認できた事件: 確定から 1 年で削除
      - 確定が確認できない事件: その事件の情報を**最後に集めた日から 2 年**で削除（新しい報道を集めるたびに数え直す）
    - 表記ゆれの吸収（NFKC・空白除去・異体字の対応表）で一致しない場合はハッシュに頼らず、複合一致と `link_confidence: low` で扱う
    - 氏名の原文はハッシュ計算の間だけ使い、ログ・ファイルに残さない

※ 全件自動での一般公開・裁判官名の掲載・少年事件・被告人属性の掲載は、いずれも法的リスクが比較的高い。公開前に弁護士など専門家の確認を受けることを強く推奨する。

## 12. 試行（非公開でのデータ蓄積）

### 12.1 期間と範囲
- 公開: **非公開**（公開サイトは閲覧制限をかけ、関係者のみ確認する）
- 収集期間: **2026年1月1日以降**の報道・判決（過去分は `backfill: true`）。新しいものから過去へさかのぼる
- 試行中の通常分（新着）は 1 日 1 回バッチ、上限は報道 50 件・判決 20 件／日
- 過去分は通常分とは別枠で、**1 日 30 件**（報道・判決の合計）から始め、Muse の実測で調整する
- 情報源は無料で公開されている記事に限る。新聞社の有料記事データベース（ヨミダス、朝日新聞クロスサーチ、毎索、日経テレコン）は、通常契約の規約で自動収集・蓄積・AI 解析・公開が禁止されているため使わない（使う場合は各社との個別ライセンス契約が前提）

### 12.2 対象犯罪（5 分類）
| 分類 | 主な罪状 | 主に確かめること |
|---|---|---|
| ① 詐欺 | 詐欺、特殊詐欺、電子計算機使用詐欺 | 共犯の被告人ごとの判決、執行猶予と実刑の分かれ方、被害額 |
| ② 交通 | 酒気帯び・酒酔い運転、危険運転致死傷、過失運転致死傷、ひき逃げ（救護義務違反）、妨害運転、無免許運転 | 交通の罪状辞書、道交法と自動車運転処罰法の組み合わせ、裁判員裁判 |
| ③ 殺人・傷害致死 | 殺人、殺人未遂、傷害致死 | 未遂の扱い、死刑・無期を含む法定刑、事件のひも付け |
| ④ 薬物 | 覚醒剤取締法違反、大麻・麻薬関係の違反 | 同種判決との比較指標の安定性 |
| ⑤ 窃盗 | 窃盗、住居侵入・窃盗、万引き、空き巣 | 複数罪状の区切りと判定、被害額・被害者数 |

- 上記に当てはまる**少年事件は含める**（§9-3 の表示ルールの検証を兼ねる）
- **性犯罪は第 2 段階**に回す（自動チェックの検証後に追加。2023年7月改正前後の法定刑の扱いもその時に検証する）
- 上記以外の犯罪は試行では送らない

### 12.3 試行で測ること
| 項目 | 内容 |
|---|---|
| 項目ごとの充足率 | 求刑・裁判長名・性別・年齢・被害額などが取れた割合 |
| 未分類率 | 罪状辞書で法律を判定できなかった罪状の割合 |
| ひも付けの正しさ | `link_confidence: high` のひも付けを抜き取りで人が確認 |
| 重複・自動チェック | 重複件数、自動チェック（§9-8）に引っかかった件数 |
| 件数と利用枠 | 1 日あたりの件数（通常分・過去分）、Muse の利用枠の消費 |

### 12.4 受信 API ができるまで
- Muse は集めたデータを §5 の形式（`schema/ingest.schema.json`）でファイルに保存しておき、受信 API ができたら過去分としてまとめて送る
- 受信 URL・Bearer トークン・HMAC の鍵は Notion やリポジトリに書かず、別の方法で渡す
